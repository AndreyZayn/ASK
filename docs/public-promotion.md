# Promoting reusable improvements

Private workspaces can accumulate useful changes to templates, schemas, and guidance. Review each improvement before adding it to the public ASK distribution.

For every reusable system change, classify it as private-only, reusable and pending, or public. A reusable candidate should be generalized into neutral defaults, templates, documentation, or synthetic examples and tests. Keep personal notes, real identities, private paths, custom agent policies, private inventories, operational data, and private history out of the candidate.

Sanitize and review the candidate before publication. Validate the public files and inspect the proposed change for owner-specific material. Publish only the reviewed generic version. Track the source-to-public status privately when needed.

Do not mirror a raw private folder into the public repository or transfer private Git history. Public software upgrades change the distribution only. They do not automatically overwrite installed private configuration, schema customizations, or notes. Compare schema and template diffs explicitly and apply reviewed changes yourself; see [upgrades](upgrades.md).
