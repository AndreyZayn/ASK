# Development Log Format

Use a project's existing development log for meaningful planning, implementation, review, verification, rework, blockers, and delivery. An entry identifies the work, date, phase, state, responsible owner, affected codebase, relevant links, outcome or evidence, and next action when applicable. Keep it concise and update one entry as work progresses; do not paste transcripts, credentials, or full test logs.

Maintain the project's index of active work and recent entries when it uses one. Decisions and durable product behavior belong in their owning project notes, not only in a log. Do not create a new log hierarchy solely to record routine activity without the owner's direction.
