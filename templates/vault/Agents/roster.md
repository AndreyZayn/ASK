# Agent Roster

No agents are enrolled. The owner may register a stable local ID, runtime, approved scope, and responsibility here. Do not copy account names, credentials, or identities into this public template. See [[Agents/ontology]]; an entry does not grant filesystem or service access.

## Enrolling the installing agent

An owner request to install or connect this agent includes a narrow roster registration. Read existing entries first: retain an enrolled identity's ID, use a distinct locally agreed ID for a different agent, and resolve actual collisions before writing. Record these fields in the existing layout:

| Agent ID | Runtime | Surface | Role | Agreed scope | Responsibility | Recorded |
| --- | --- | --- | --- | --- | --- | --- |

A runtime is a host; a model and a professional hat are not an agent identity. A row does not grant filesystem access, external actions, delegation, installation, or policy authority. Preserve other agents and owner commentary. When adding the first real record, replace the obsolete empty sentence and update lifecycle/date metadata according to the local schema.

Use the public distribution's `docs/onboarding.md` for first and additional agents. Its `agent onboarding` command only prepares a read-only plan or proposed rows from sanitized observations; the installing agent still reviews and applies authorized notes through [[knowledge-continuity-loop]]. Roster registration, persistent bootstrap, fresh-session proof, and [[Agents/capabilities/INDEX|capability documentation]] are separate outcomes. Keep registration pending when writes are not permitted.
