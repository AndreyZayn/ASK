# Software Practice Improvement Loop

## Purpose and entry

An evidence-based engineering workflow or harness diagnosis. Read the existing project context and the current task checkpoint. A missing material criterion returns that specific gap to planning; ordinary implementation choices stay within execution.

## Primary hat

[[Agents/hats/cto]]. A hat does not require a separate agent. Independent review requires a distinct reviewer when warranted; renaming the author's role is not independence.

## Iteration and feedback

Collect the smallest relevant incident evidence, identify the recurring mechanism, and propose a bounded correction. Separate failed tooling, missing authority, implementation defects, and instruction defects. Evaluate an authorized change against the original failure without turning diagnosis into broad rewrites. Iterate on acceptance failures within scope. After two failed repairs of one problem, change the approach under [[Agents/rules/task-completion]].

## Done and stopping points

An evidence-backed diagnosis, recommendation, or verified authorized process change; no automatic installation or scheduling. Stop at that boundary, report dependent blockers precisely, and continue independent authorized work. Reading this definition does not start another loop, invoke an agent, grant deployment authority, or schedule work.
