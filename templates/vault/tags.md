# Tag Conventions

Tags help browse, not authorize work. Prefer a small, stable set of lowercase topic words. Create new tags only when they improve retrieval; do not encode secrets, identities, or unverified claims in tags. See [[frontmatter-schema]] for syntax.

The installed schema enforces this starter vocabulary: `agents`, `bootstrap`, `capabilities`, `communications`, `continuity`, `daily`, `delegation`, `goals`, `index`, `integrations`, `logs`, `loops`, `memory`, `monthly`, `ontology`, `people`, `personal`, `plugins`, `projects`, `roster`, `routing`, `rules`, `runtimes`, `schema`, `skills`, `structure`, `tasks`, `taxonomy`, `weekly`. Keep this note and the local schema enum aligned. Project-specific path rules may provide a reviewed superset.
